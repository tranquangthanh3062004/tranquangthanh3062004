## 🧩 How I code & learn — a practical, open-source inspired approach
Influenced by leading open-source maintainers and platform engineers, I follow an evidence-based, iterative approach:

1. Research before building — review prior art, papers, and notable implementations.  
2. Small, focused experiments — short iterations with clear success criteria; prefer reproducible notebooks for exploration.  
3. Test-driven where it matters — unit tests for core logic and integration tests for pipelines.  
4. Document decisions — every non-trivial design has a short rationale in repo docs or design notes.  
5. Automation & reproducibility — CI, linting, pinned dependencies, and Docker images to ensure portability.  
6. Small PRs, fast feedback — prefer incremental contributions that are easy to review and merge.  
7. Share early, improve publicly — open-source minimal prototypes, invite feedback, and iterate in the open.  
8. Measure & observe — add metrics and lightweight monitoring to validate behavior in production.

This mixes research rigor with production engineering discipline: ship small, test well, document decisions, and iterate.
